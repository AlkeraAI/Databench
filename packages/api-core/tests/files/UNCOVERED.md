# Files coverage gaps

`make files-coverage` measures line and branch coverage of the Files sources
and fails below 95%. A percentage alone lets gaps pile up under the floor, and
a `# pragma: no cover` hides a gap completely, so the floor is paired with this
file.

`scripts/check_files_uncovered.py` enforces three rules:

- Every line the suite does not execute (a missing line, or the source line of
  a branch arc that is never taken) is a row here, with a reason.
- Every `# pragma: no cover` in the Files sources is a row here too.
- A row whose line is now covered and carries no pragma fails the check, so
  stale rows cannot hide the next real gap.

A gap a test could reach gets the test, not a row. A row is for a line this
platform or build stage cannot execute: a Linux-only syscall on a macOS run, a
Windows branch, a driver that does not exist yet. Never write a filler test to
delete a row.

A row marked **Reachable** is a debt: the line can be executed in-process, and
the row names the suite that owes it a case. Writing that test and deleting
the row is always the right move.

`excerpt` names each line by its own stripped text, in backticks, so an edit
above a gap never stales the row. A line that appears more than once in the
file carries the occurrence it means, for example `return None` (#3).
